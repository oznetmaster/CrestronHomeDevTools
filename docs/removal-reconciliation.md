# Reconciling an interrupted final removal

Final removal is a phase-two NUnit check. If removal has already happened but its final UI or cleanup recording was interrupted, never reinstall or remove the driver again merely to obtain a green result. The original attempt and failure remain authoritative evidence of that interruption.

The automation command `--accept-removal-reconciliation --settings FILE --settings-sha256 PIN --reconciliation-plan FILE --reconciliation-plan-sha256 PIN` accepts a separately inspected, read-only verification. It holds the workflow lock, requires the original worker to be stopped on its recorded host, and binds the unchanged final-test checkpoint, candidate, original removal intent, postchecks and endurance receipt. It performs no equipment or network operations and does not itself advance the workflow.

The version-one request identifies the exact checkpoint and original-evidence digests, the independently inspected diagnostic evidence directory and inventory digest, its retained producer source and digest, and who inspected it. The diagnostic must retain the original file inventory, original owner and failure/plan digests, pre/post API inventories, complete after-only UI traversal and Home restoration, the final error-log snapshot and comparison with the original pre-removal log, and confirmed reservation release. Its completion must declare no physical action or removal replay. These flags are insufficient on their own: acceptance recomputes the inventory, scope, preservation, UI membership and log conclusions from the producer files.

Accepted proof is copied beneath `removal/reconciliation`. The original `removal/operation/failure.json` is preserved, and no replacement original `operation/result.json` is written. A distinct reconciled result and acceptance record bind all retained proof. Later finalization and review verify it again. Missing files, changed identities, a remaining child or orphan, incomplete traversal, lost log continuity, new errors, unreleased ownership or replay cannot pass. A partial copy/observation commit is retained for inspection rather than reset.

After acceptance, select the ordinary shared NUnit post-endurance/removal case. It verifies the retained postchecks and removal proof, writes the completed test boundary, and stops before phase-three document work. Physical tests and endurance are reused only through their original unchanged receipts.
